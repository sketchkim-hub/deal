# 오늘의특가 — 기획안

쿠팡에서 **15% 이상 할인 중인 상품**만 골라 보여주고, 하루 3번 가격을 다시 확인해 변동을 반영하는 쿠팡 파트너스 제휴 사이트.

---

## 1. 목표

| 목표 | 기준 |
| --- | --- |
| 방문자가 "지금 싸게 살 수 있는 것"을 3초 안에 찾게 한다 | 첫 화면에 할인율·가격·썸네일이 보이는 카드 8개 이상 |
| 가격 정보를 믿을 수 있게 한다 | 모든 카드에 "가격 확인 시각" 표시, 하루 3회(09·15·21시) 재확인 |
| 파트너스 수익 | 모든 구매 버튼은 파트너스 단축링크로 이동 (클릭·구매 통계는 파트너스 리포트) |
| 운영 부담 최소화 | 단축링크 하나만 붙여넣으면 상품 정보·썸네일·가격이 자동으로 채워짐 |

## 2. 현재 제약과 해결 방법

| 제약 | 해결 |
| --- | --- |
| 쿠팡 파트너스 Open API 미승인 | **1단계(지금)**: 관리자가 파트너스 사이트에서 만든 단축링크(`link.coupang.com/a/...`)를 붙여넣으면, 시스템이 링크를 따라가 상품 페이지를 찾고 제목·썸네일·가격·할인율을 읽어옵니다.<br>**2단계(API 승인 후)**: `.env`에 Access/Secret Key만 넣으면 단축링크 자동 생성(Deeplink API)과 골드박스 특가 자동 수집이 켜집니다. 코드는 이미 들어 있습니다. |
| 해외 IP로 접속하면 쿠팡이 차단하거나 다른 페이지를 보여줌 | 가격 확인은 **집 PC(가정용 한국 IP)** 에서만 실행합니다. 시작 전에 IP 국가를 확인하고, `KR`이 아니면(VPN 등) 멈추고 관리자 화면에 기록합니다. |
| 서버 운영 비용·관리 부담 | 사이트는 **GitHub Pages 또는 Firebase Hosting**(무료)에 정적 페이지로 게시합니다. 집 PC가 확인할 때마다 페이지를 새로 만들어 자동으로 올립니다. 집 PC가 꺼져도 사이트는 계속 열립니다. |
| 쿠팡 페이지 구조 변경 | 파서가 여러 방식(메타 태그 → JSON-LD → 화면 요소)을 차례로 시도하고, 화면 요소 선택자는 `src/coupang/selectors.js` 한 곳에 모아 두어 쉽게 고칠 수 있습니다. |

## 3. 핵심 기능

### 3.1 방문자 화면
- **홈(오늘의 특가)**: 할인율순 카드 그리드, 카테고리·할인율(15/30/50%+) 필터, 정렬(할인율/낮은 가격/절약액/최신)
- **"방금 가격 내려갔어요"** 가로 스크롤 영역: 직전 확인보다 가격이 내려간 상품
- **다음 가격 확인까지 카운트다운**: 하루 3회 갱신된다는 것을 보여줘 재방문 유도
- **상품 상세**: 큰 썸네일, 가격 변동 그래프, 공유 버튼(카카오톡 등 모바일 공유 시트)
- 모든 페이지 상단·하단에 파트너스 고지 문구

### 3.2 관리자 화면 (집 PC의 `http://127.0.0.1:3000/admin`, 그 PC에서만 열림)
- 상품 등록: 파트너스 단축링크(필수) + 상품 URL(선택) + 카테고리 → 즉시 1회 가격 확인
- 여러 개 한 번에 등록(한 줄에 하나씩)
- 상품 목록: 상태(노출 중/할인 부족/품절/오류), 현재가, 할인율, 마지막 확인 시각, 게시 상태("지금 게시" 버튼)
- "지금 전체 확인" 버튼, 실행 기록(성공/실패 수, 접속 IP 국가)
- 후보 목록: 특가 목록 페이지를 훑어 찾은 15%+ 상품. 파트너스 링크를 붙이면 바로 게시

### 3.3 모니터링 규칙
| 확인 결과 | 처리 |
| --- | --- |
| 할인율 ≥ 15% | 노출(`active`) |
| 할인율 < 15% | 자동 숨김(`below`). 다음 확인에서 다시 15% 이상이면 자동 복귀 |
| 품절 | 숨김(`soldout`) |
| 확인 실패 | 직전 정보 유지(`error`). 마지막 성공이 24시간을 넘으면 숨김 |
| 가격 변동 | 직전 가격을 저장해 "▼ 3,000원 인하" 표시, 이력은 최근 90회 보관 |

- 확인 시각: 매일 **09:00 / 15:00 / 21:00 (한국 시간)**, `.env`의 `CHECK_TIMES`로 변경
- 상품 사이 3~8초 무작위 대기(쿠팡 서버 부담과 차단 위험 최소화)

## 4. 시스템 구성

```
┌──────────────────── 집 PC (한국 IP) ────────────────────┐
│ 관리자 화면 http://127.0.0.1:3000/admin (이 PC에서만 열림) │
│ data/db.json  ← 상품·가격 이력                            │
│                                                          │
│ 09·15·21시 ─▶ IP 국가 확인(KR?) ─▶ 쿠팡 상품 페이지 확인    │
│               (일반 요청 → 차단되면 Chromium으로 재시도)     │
│            ─▶ 정적 사이트 생성(dist/) ─▶ 자동 게시 ─────────┼──┐
└──────────────────────────────────────────────────────────┘  │
                                                              ▼
                     [GitHub Pages 또는 Firebase Hosting] ◀── 방문자 (내 도메인, HTTPS)
```

- 런타임: Node.js 20+, 외부 의존성 `cheerio` 1개 (+ 선택 `playwright`)
- DB: JSON 파일 1개 (상품 수천 개까지 충분, 백업은 파일 복사)
- 사이트: 완성된 HTML 파일만 게시 → 검색엔진 노출·첫 화면 속도에 유리, 해킹될 서버가 없음
- 구매 버튼은 파트너스 단축링크로 바로 연결 (클릭 통계는 쿠팡 파트너스 리포트에서 확인)
- PC가 정시에 꺼져 있었으면 켜진 직후 밀린 확인을 실행, 24시간 넘게 갱신이 없으면 사이트에 "가격 정보가 오래됨" 안내 표시

## 6. 준수 사항 (중요)

1. **파트너스 고지 문구**: "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." — 모든 페이지 상단과 하단에 자동 표시됩니다. 지우지 마세요.
2. **가격 표시**: 가격은 확인 시점 기준이며 실제와 다를 수 있다는 안내와 확인 시각을 함께 표시합니다.
3. **자동 수집 관련 위험**: 쿠팡 이용약관은 허가 없는 자동 수집을 제한합니다. 이 시스템은 *직접 등록한 상품만, 하루 3번, 느린 간격으로* 확인하도록 설계해 부담을 최소화했지만, 위험이 0은 아닙니다. **Open API가 승인되면 API 방식으로 옮기는 것을 권장합니다**(설정만 바꾸면 됩니다). 후보 자동 탐색(목록 페이지 훑기)은 기본으로 꺼져 있습니다.
4. 가짜 후기, 허위 "마감 임박", 부풀린 조회수 같은 표시는 넣지 않았습니다.
